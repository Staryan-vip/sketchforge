# SketchForge — Requirements

## User stories
- As a user, I can draw screens on a canvas, so my layout idea is captured without writing code.
- As a user, I can upload a photo of a paper sketch, so offline ideas are not lost.
- As a user, I can add a voice note (or typed equivalent), so intent and logic are captured in plain language.
- As a user, I can see and edit a generated spec before code is built, so wrong interpretations can be fixed early.
- As a user, I can see a live preview of a runnable prototype, so the result is demonstrable, not just a mockup.
- As a user, I can iterate by chatting, so a change does not require rewriting the whole app.
- As a user, I can export the prototype to GitHub, so work is portable.

## Acceptance criteria
- Sketch + voice input produces a spec with screens, features, and user flows.
- Spec editing changes what is built next.
- Preview is runnable in a browser and reflects the latest spec.
- Export produces a repository with source, README, and license.
- No feature in the submission story is claimed unless it exists in the repo or demo.
